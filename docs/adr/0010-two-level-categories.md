# ADR-0010：分类体系扩展为两级

- 状态：Accepted
- 日期：2026-09-13
- 相关：[ADR-0002](./0002-data-layering.md)、[ADR-0009](./0009-open-catalog.md)

## 背景

M5 打通自主收录管线后，条目数从 322 增至 336 并计划继续扩量，但分类维度没有跟上：

| 分类    | 条目数 | 问题                                                    |
| ------- | ------ | ------------------------------------------------------- |
| `infra` | 80     | 混装了 API 聚合网关、推理算力、云厂商与机构主体四类内容 |
| `model` | 45     | 基础模型厂商与具体模型、API 平台混装                    |
| `agent` | 36     | 编排框架与终端/桌面 Agent 应用混装                      |
| `image` | 33     | 生图、设计编辑与 3D 生成混装                            |

竞品 AI工具集（ai-bot.cn）采用两级分类（如「AI图像工具 → 背景移除 / 无损放大 / 商品图 / 3D」）。
继续增加条目而不细化分类，只会让分类页变成一堵墙。

## 决策

1. **`Category` 新增 `parent` 字段，仅支持两级**：不填为一级分类，填了为二级分类；
   `validate:data` 校验 `parent` 必须指向一个一级分类（禁止三级）。
2. **`Site.category` 存最精确的分类**（可能是二级），不新增 `subcategory` 字段 ——
   搜索、筛选、导航、详情页面包屑都只处理一个字段。
3. **父分类页聚合子分类条目**：`getCategoryScope(slug)` 返回「自身 + 子分类」，
   `getSitesByCategory` 据此过滤；一级分类的 `count` 也是聚合值。
4. **平票时更深的分类优先**（`resolveCategory`）：下放到二级的关键词通常仍保留在父分类中
   （如 `groq` 同时在 `infra` 与 `inference`），若沿用「平票取 order 小者」，父分类会永远胜出、
   二级分类形同虚设。
5. **只细分失衡的四个大分类**（infra / model / agent / image，共拆出 10 个二级），
   其余六个分类保持扁平，避免一次性大改。
6. **迁移限定在同一子树内**：`migrate:categories` 的候选集固定为「父分类 + 其子分类」，
   未命中任何子分类时保持原值，因此不会把条目误迁到别的一级分类。

## 理由

- **单字段最简洁**：新增 `subcategory` 会让筛选、搜索索引、排序、API 都要处理两个字段与回退逻辑；
- **父分类天然兜底**：厂商主体等无法细分的条目（如 Apple、Google、AWS）留在父分类，
  聚合视图仍能完整展示，不必为它们硬造分类；
- **URL 扁平**：二级分类同样是 `/category/<slug>`，SEO 语义清晰、sitemap 无需特殊处理；
- **可渐进**：未细分的分类不受影响，后续可随时按同一套机制补充二级。

## 约束与代价

| 约束           | 说明                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| 两级上限       | `parent` 不得指向二级分类，`validate:data` 拦截三级结构                    |
| slug 全局唯一  | 一级与二级分类共用一个命名空间，新增时需避免撞名                           |
| 关键词重复     | 子分类关键词通常与父分类重叠，因此依赖「平票更深优先」而非移除父分类关键词 |
| 数据迁移       | override 中显式钉死 `category` 的 243 条需经 `migrate:categories` 改写文件 |
| 父分类仍需承载 | `infra` 迁移后仍保留 29 条兜底条目（厂商主体），其分类页条目数依然较多     |

## 备选方案

| 方案                        | 否决原因                                                            |
| --------------------------- | ------------------------------------------------------------------- |
| 新增独立 `subcategory` 字段 | 筛选/搜索/排序/API 都要处理双字段回退，复杂度显著上升               |
| 用标签承载二级维度          | 标签与分类语义重叠，且标签无标题、无描述，无法生成有内容的落地页    |
| 一次性重构全部 10 个分类    | 改动面过大、迁移风险高，且 `writing`（7 条）等小分类暂无细分必要    |
| 三级或任意深度              | 数据模型与 UI（导航、面包屑）复杂度不成比例，两级已足够表达目录结构 |
